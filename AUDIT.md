## P0 — Безопасность. Сделать в первую очередь. Фронтенд НЕ затрагивает.

> Примечание: `.sql`-дамп и `.git` есть **только локально**, на прод-сервере их нет (подтверждено PM). Поэтому они понижены до «локальной гигиены» (см. P3), а боевой приоритет №1 — админка.

### [x] 1. Укрепление входа в админку (`admin.php`) 🔴 — ГОТОВО
- [x] **Session fixation:** `session_regenerate_id(true)` после успешного входа.
- [x] **Дефолтный пароль `12345`:** fallback убран; при пустом `admin_password` вход запрещён.
- [x] **Тайминг:** сравнение пароля и reset-токена через `hash_equals()`.
- [x] **Защита от перебора:** лимит 5 попыток по IP → блок на 15 мин (файл `../login_throttle.json`, деградирует мягко, если каталог не пишется).
- [x] **CSRF-токены** на всех 4 формах (вход / сохранение / забыли пароль / новый пароль) + серверная проверка `csrf_check()`.
- [x] **Домен в письме:** `HTTP_HOST` заменён на константу `SITE_DOMAIN` (ссылка сброса, тема, `From`).

*Хорошее в админке:* пароли хешируются (`password_hash`/`password_verify`), поля сохранения whitelisted (нет mass-assignment), reset-токен на `random_bytes(32)` с истечением 1 ч.

### [x] 2. Reflected XSS через адрес страницы 🔴 (исправлено)
- **Где точно:**
  - `header.php:52` — `<meta property="og:url" content="<?= $canonical_url ?>">`
  - `header.php:58` — `<link rel="canonical" href="<?= $canonical_url ?>">`
  - `header.php:59–61` — `alternate hreflang` ссылки (`$protocol.$host.$link_ru/$link_ua`)
  - `menu.php:45,57` — переключатель языка (`$switch_link`)
- **Проблема:** всё это строится из `$_SERVER['REQUEST_URI']` и `$_SERVER['HTTP_HOST']` — управляется посетителем и печатается в HTML **без экранирования**.
- **Фикс:** `htmlspecialchars(..., ENT_QUOTES, 'UTF-8')` **только** на этих reflected-значениях (URI/Host-производные). Это URL, не контент — вёрстка не пострадает. CMS-контент не трогать (см. п.8).

### [~] 3. Пароль БД вынесен из кода
- [x] Креды вынесены в `secrets.php` **над** корнем сайта; `db.php` читает их через `__DIR__.'/../secrets.php'`. В `db.php` пароля больше нет. В git добавлен `secrets.sample.php` (шаблон), реальный `secrets.php` в `.gitignore`.
- [ ] **Осталось (за тобой, на хостинге):** сменить сам пароль пользователя БД в панели → вписать новый в `secrets.php` на сервере. Сейчас там прежнее значение, чтобы сайт не лёг.
- ⚠️ **При деплое:** файл `secrets.php` должен оказаться в каталоге **над** `public_html` (рядом лежит локально в `D:\evakuator-kharkov.kh.ua\secrets.php`). Без него `db.php` выдаст явную ошибку — не тихий сбой.

## P1 — Баги и корректность

### [ ] 6. Разное определение языка в двух местах
- **Где:** `config.php:19` `strpos($current_uri, '/ua') === 0` (без слэша!) и `router.php:16` `strpos($slug, 'ua/') === 0` (со слэшем).
- **Проблема:** в `config.php` страница вроде `/uaz-evakuator` определится как украинская (`/ua` совпадает с началом). Плюс рассинхрон логики между файлами.
- **Фикс:** одна функция определения языка, проверка строгая: `str_starts_with($uri, '/ua/') || $uri === '/ua'`.

### [ ] 7. Мёртвый код и дубли в `config.php`

- Ветка `else` (стр. 46–52) недостижима — она внутри `if ($db_page)`, где `!empty($db_page)` всегда `true`.
- **Фикс:** переписать блок 25–68 без дублей и мёртвых веток.

## P2 — Качество кода (постепенно, аккуратно)

### [ ] 8. ⚠️ ВАЖНО: НЕ экранировать контент из CMS «на всякий случай»
Кими советовал обернуть весь вывод в `htmlspecialchars`. **Так делать нельзя** — это сломает работающий сайт.
- В `render_structured_content()` и `apply_placeholders()` (`theme_functions.php`) контент блоков — это намеренный HTML, который вводит админ (жирный, ссылки, разметка).
- Обернёшь всё в `htmlspecialchars` → вся вёрстка контента превратится в текст с видимыми `<p>`, сайт визуально поедет.
- Источник этих данных — **только админка за паролем**. Значит правильный приоритет — защитить аккаунт админа (п.4), а не экранировать доверенный HTML.
- Экранировать нужно **точечно** и только там, где в вывод попадают данные **посетителя** (п.5).

### [ ] 9. `require_smart()` тащит 25+ `global`
- `theme_functions.php:11–15` — антипаттерн, тяжело поддерживать. Не срочно; при развитии постепенно переводить на передачу контекста массивом/объектом.

### [ ] 10. `$settings` перечитываются на каждый include
- Запрос к таблице `settings` в `config.php:8` выполняется при каждом подключении. Для малого сайта некритично. Можно static-кэш в рамках запроса.

### [ ] 11. Страница 404 — голый `echo`
- `router.php:32,39` отдают `echo "<h1>404</h1>"` без шаблона и без `noindex`. Сделать `templates/404.php`.

## Что у Кими было верно, а что нет

**Верно:** пароль БД в коде, `global` вне функции, дубль `$page`, примитивный 404, Medoo действительно защищает от SQL-инъекций, reflected XSS в `header.php` (это подтвердилось — п.2).

**Неточно / мимо:**
- «Критический баг языка в `router.php`» — там как раз всё ок (`ua/` со слэшем). Настоящий баг — в `config.php:19` (`/ua` без слэша). См. п.6.
- «XSS в `menu.php` через настройки» — названия пунктов и слаги там **захардкожены в самом файле** (`$m_lang`), не из БД. Риска нет.
- «Экранировать весь вывод» — опасный совет для этого сайта, сломает вёрстку CMS-контента. См. п.8.
- Не расставил приоритеты: самое боевое — укрепление админки (п.1) и reflected XSS (п.2), а не сплошное экранирование.
